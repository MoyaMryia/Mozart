# pipeline：开发与部署流水线

状态：讨论中。

## 目的

把构建、检查、部署、启动、观测和回滚收进一个本地入口。目标是改完代码后一条命令跑完全程，不再手工拼 rsync、ssh 和重启命令。

## 边界

- 覆盖开发机和单台 Jetson。
- 不覆盖云端 CI/CD、容器编排和多设备集群。
- 模型、音频和密钥仍在仓外，不进流水线产物。

## 一键入口（草案）

统一入口 `tools/dev.sh`，子命令：

| 命令 | 作用 |
| --- | --- |
| `doctor` | 检查本机工具链、设备连通性、L4T 版本、磁盘和依赖 |
| `build` | 按预设构建；默认主机，`--device` 构建 aarch64 |
| `test` | 调用 `tools/ci-local.sh` 的检查与测试阶段 |
| `deploy` | 构建设备产物，传到版本目录，原子切换 |
| `run` | 启动或重启服务 |
| `status` | 查询健康接口、进程和最近部署记录 |
| `logs` | 查看服务日志 |
| `rollback` | 切回上一个版本并重启 |
| `clean` | 清理旧版本和构建缓存，保留配置与资产 |

## 阶段

1. 预检：工具链版本、SSH 连通、设备架构、L4T 版本、磁盘余量。
2. 构建：主机预设用于测试；设备预设用于发布。
3. 检查：静态检查、单元测试、必要的 sanitizer。
4. 打包：记录 git 提交、构建时间、预设和资产版本。
5. 部署：上传到 `releases/<版本>/`，切换 `current` 链接。
6. 启动：重启服务，等待健康检查通过。
7. 冒烟：查询状态接口，按需跑一段音频自检。
8. 回滚：切回上一个版本，重启并复查健康状态。

## DevOps 约定

- 单一入口：本地和 CI 使用同一套命令，不重复定义。
- 幂等：重复执行不产生额外副作用。
- 原子发布：版本目录加 `current` 链接，失败不破坏上一版。
- 可回滚：保留最近若干个版本，回滚一条命令。
- 可追溯：每次部署记录提交号、时间、预设和结果。
- 配置外置：设备地址、模型路径和密钥不写进仓库。
- 安全默认：删除类操作要求显式参数；默认不覆盖资产。
- 可观测：状态接口、结构化日志和部署记录是最低要求。

## 现状

- 已有 CMake presets、`tools/ci-local.sh`、pre-commit hook 和 GitHub Actions。
- 已有主机测试与文档检查。
- 缺一键部署、设备端版本目录、启动检查、回滚和部署记录。

## 待讨论

- 入口用 `tools/dev.sh`，还是 justfile 或 Makefile。
- 设备上原生构建，还是开发机交叉编译。
- 服务用 systemd，还是简单的进程管理脚本。
- 发布目录布局和保留版本数。
- 设备地址如何配置，是否需要自动发现。
- 冒烟测试是否包含音频回录，还是只查状态接口。
- CI 是否增加 self-hosted Jetson runner。

## 验收

- 新环境按文档一条命令完成构建和检查。
- 一条命令部署到设备并启动，健康检查通过。
- 一条命令回滚到上一版。
- 每次部署都能查到提交号、时间和结果。
- 全过程不需要手工 rsync、ssh 或重启命令。
