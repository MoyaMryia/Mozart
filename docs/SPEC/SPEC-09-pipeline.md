# pipeline：开发与部署流水线

状态：讨论中。2026-11-15 起为待办清单，`[x]` 已实现、`[ ]` 未实现，记法见 [SPEC.md](SPEC.md)。

## 目的

把构建、检查、部署、启动、观测和回滚收进一个本地入口。目标是改完代码后一条命令跑完全程，不再手工拼 rsync、ssh 和重启命令。

## 边界

- [x] 覆盖开发机和单台 Jetson。
- [x] 不覆盖云端 CI/CD、容器编排和多设备集群。
- [x] 模型、音频和密钥仍在仓外，不进流水线产物。

## 阶段

1. [ ] 预检：工具链版本、SSH 连通、设备架构、L4T 版本、磁盘余量。
2. [x] 构建：主机预设用于测试；设备预设用于发布。
3. [x] 检查：静态检查、单元测试、必要的 sanitizer。
4. [ ] 打包：记录 git 提交、构建时间、预设和资产版本。现仅 stdout 摘要（`deploy-jetson.sh:250-252`）。
5. [ ] 部署：上传到 `releases/<版本>/`，切换 `current` 链接。与 SPEC-04"cargo 产物目录为唯一部署目录、子进程同目录解析"冲突，见 SPEC.md 跨模块冲突。
6. [ ] 启动：重启服务，等待健康检查通过。
7. [x] 冒烟：查询状态接口，按需跑一段音频自检。（`tools/jetson-smoke.sh`；release 构建前置为手工步骤）
8. [ ] 回滚：切回上一个版本，重启并复查健康状态。

## DevOps 约定

- [x] 单一入口：本地和 CI 使用同一套命令，不重复定义。（`tools/ci-local.sh` 为检查单源）
- [x] 幂等：重复执行不产生额外副作用。
- [ ] 原子发布：版本目录加 `current` 链接，失败不破坏上一版。未做（布局待决策）。
- [ ] 可回滚：保留最近若干个版本，回滚一条命令。
- [ ] 可追溯：每次部署记录提交号、时间、预设和结果。
- [x] 配置外置：设备地址、模型路径和密钥不写进仓库。
- [x] 安全默认：删除类操作要求显式参数；默认不覆盖资产。
- [x] 可观测：状态接口、结构化日志和部署记录是最低要求。（部署记录除外，见上）
