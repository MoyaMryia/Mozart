# 输出模式转换与补偿

本文是设计研究。已实现项由 [SPEC-04](SPEC/SPEC-04-daemon.md) 和 [SPEC-05](SPEC/SPEC-05-language.md) 标记。

## 哪些状态可以反变换

把模式切换写成按序执行的动作，而不是一条同时设置多个布尔值的赋值。每个动作都记录执行前状态和执行结果：`已确认`、`明确拒绝`、`结果未知`。补偿只处理已生效或可能生效的副作用；不能拿命令超时当成“什么也没发生”。

可逆控制状态、需确认的资源归还和不可逆结果要分开：

| 动作 | 对应的反向动作 | 不能恢复什么 |
| --- | --- | --- |
| 改变路由请求 | 提交上一请求或新的用户意图 | 不能用旧请求覆盖更新一代的用户意图。 |
| 启动 RVC 流 | 停止该流并确认租约归还 | 停止后重启是新会话，不恢复推理缓存或已丢帧。 |
| 允许 TTS 播报 | 撤销本代播报许可 | 已交给声卡的尾音按约定排尽或截断；已经播放的声音不能撤回。 |
| 字幕落盘 | 追加新修订或失败原因 | 不回滚已发布的记录，不以补偿触发第二次播报。 |

因此 `A → B → A` 只要求恢复 **A 的策略和资源条件**，不要求逐位恢复音频和推理历史。应答归属于自己的转换代次；迟到的应答不能完成新转换。对 RVC 而言，已确认的幂等 `StopStream` 应答可作为归还证据，轮询开始时采到的旧快照不行。

## 状态所有权

- **daemon**：输出策略的请求与应用、RVC 租约、模式过渡与对账。RVC 租约不是 Jetson 上的整机 GPU 独占；翻译服务和可配置的 TTS 后端有独立的运行状态。
- **pre**：实际选源、扬声器淡变、播报帧准入和输出边界。接收路由命令的应答不代表淡变已经结束。
- **ASR**：共享采集下的在线解码、逐句复核与事件代次。它可复核上一句，同时识别下一句。
- **bridge／TTS**：bridge 拥有字幕、翻译及播报投递；TTS 拥有合成任务。翻译完成、TTS 受理、实际出声是三个不同事实。

## 转移表

直出、实时变声和翻译播报均保持识别与翻译字幕可用。文件转换是独立任务，不是第四个输出模式。

| 目标与前置条件 | 正向转换 | 失败或切回时的补偿 |
| --- | --- | --- |
| 进入实时变声，RVC 租约空闲 | 确认匹配实时流，再下发 `SetRoute(rvc)`。 | 路由明确拒绝或结果未知时，保留上一个已应用路由；停止可能已启动的流，待确认后才能再分配。 |
| 实时变声切直通 | 先下发 `SetRoute(direct)`，再停实时流。 | 路由应答已确认而停流未知时，报告直通和实时租约待归还。不准文件接管；同一租约上可重复停流对账。 |
| 实时变声切翻译播报 | 先从实时流切出，再发布新的播报许可；字幕链不重启。 | TTS 未就绪时保持字幕，报告播报未就绪。确认许可是否已生效再决定撤销，不把超时当静音。 |
| 翻译播报切直通或实时变声 | 先撤销旧播报代次；bridge 不再提交、TTS 中止、pre 拒绝旧代音频。再完成目标输出。 | 切回播报创建新代次，不重投旧句。对已经送入 ALSA 的尾音另设完成条件，不把清空应用队列当作静音。 |
| RVC 文件任务占用资源 | 保留当前输出，更新最近一次实时变声意图。 | 文件终态与 RVC、共享 socket 的归还分开确认；确认归还后再评估待处理意图。 |

当前实现收口实时 RVC 租约和字幕桥的播报准入。桥在首次处理 `final` 时绑定代次；复核、翻译和重连不更新资格。旧句可以继续发布字幕，但撤销许可后不能从桥新发起 TTS 提交。等待播报任务不占用队列锁，清理不与空队列等待争锁。

daemon 的 `speech stop` 已接通严格停止：桥撤销许可并返回同机时钟截止值，TTS 确认停止发出旧代帧，pre 在播放边界确认拒绝旧代帧。失败留待对账，不允许重新开启；已提交给 ALSA 的尾音自然播完。

统一入口为 `mozart-ctl mode <direct|rvc|broadcast>` 或 `PUT /api/v1/mode`。请求返回模式过渡快照；用 `status --json` 的 `output_mode.applied` 查询是否生效。翻译播报空窗静音，另外两种托管模式不插播 TTS；单项路由或播报命令取消托管模式。托管模式下重启的桥在 daemon 重新下发许可前不播报。具体证据见[本机联调报告](../reports/speech-fence-20261123/RESULTS.md)。

## ASR 逐句收尾

复核未决不是模式切换的阻塞条件。桥以启动号与句号识别句子；复核缺失达到单调时限，或桥重启时恢复到未决记录，便封存在线原文并继续文字翻译。迟到复核不覆盖封存结果。这不是事件送达保证：尚未落盘或超出有界恢复窗口的事件不能恢复。完整持久事件日志、落盘确认和跨进程幂等仍是独立设计。

## 验收顺序

1. 注入停流执行前断连、执行后丢应答，验证租约未确认前文件仍排队，下一次实时请求也不能起流。
2. 对 `播报 → 实时变声 → 播报` 注入 TTS 定拍等待、在途数据报、服务重启或应答乱序。确认旧播报无回灌，新的原文与译文继续更新，ASR 启动号不变。
3. 在原文已落盘且复核未决时结束 ASR 或 bridge，注入事件淘汰与迟到复核。验证只出现一个终态，不重复播报。
