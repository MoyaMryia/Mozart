# FUTURE：第一版之后的提升点

状态：待讨论。最后更新：2026-11-12。

本文件只记录已经讨论过、明确推迟到第一版之后的条目。
没有讨论过的想法先不进这里，避免把清单写成愿望池。

| 项 | 场景与动机 | 影响模块 | 前置条件 |
| --- | --- | --- | --- |
| 在线参数调整（SetParams） | 调 `pitch_shift`、`index_rate` 时不中断音频。第一版走 `StopStream` → `StartStream`。 | rvc、daemon | 控制面加命令；C++ 在块边界读参数快照；防抖与状态回报。 |
| 回声抑制 / 回声消除（AEC） | 扬声器播出的变声或播报被麦克风再次拾取，形成回声甚至啸叫。 | pre、core | DSP 阶段接口预留参考帧；播放侧提供带时间戳的最终混音参考环；板端测 ERLE（回声抑制量）和双讲（双方同时说话）。 |
| 降噪器切换 | 默认继续用 WOLA；保留切换能力，便于以后对比 DTLN、RNNoise。 | pre | 统一降噪器接口；固定输入逐阶段对拍；板端 CPU 与延迟预算。 |
| 共享内存环形缓冲 | 已评估：当前 20 ms 帧率下 Unix 数据报足够，暂不采用；只有实测抖动或 CPU 压力不够时才做。 | core、pre、rvc | 跨进程 SPSC（单生产者单消费者）、丢最旧、生命周期管理。 |
| F0 中值滤波（`filter_radius`） | 旧 C++ 只保存参数、未参与计算。v1 不暴露死参数；保留为提升项，推迟实现。 | rvc | 中值滤波实现；与 Python 参考逐帧对拍；实现后暴露到 `StartStream`。 |
| 资源仲裁扩展到扬声器与播报 | v1 基础链路只做 GPU 单资源仲裁，扬声器仲裁留接口。翻译播报活动（占 GPU 与扬声器）接入仲裁推迟。 | daemon、pre、rvc | 播报活动定义；扬声器仲裁规则；板端验证切换延迟。 |
| 播报与实时输出的分时 / 混音 | 翻译播报经变声链路输出，与实时变声共用扬声器。分时（播报时静音实时）还是同时混音未定。 | daemon、pre | 扬声器仲裁；板端测混音可懂度与延迟。 |
| 提前断句翻译（stable_clauses）与断句模型 | 流式识别中提前切稳定子句翻译以降低延迟。旧实现为可选、演示默认关，第一版只做整句翻译。规则版（stable_cut）与可选 NNSplit 断句模型一并推迟。 | language | 第一版整句翻译稳定后；子句状态机、更正处理、子句汇总搬 Rust 并对拍；断句模型另需 onnxruntime（ort）与模型文件。 |
| 灵活变速（flexible tempo） | 播报按时长比例（预测播报时长 / 源时长）与积压反馈选 1.0–1.5 倍速、保留音高。第一版播报原速。 | language、pre | 播报播放路径定（含共用扬声器仲裁）；时长模型按新目标音色重标定（旧为 Qiqi + PocketTTS）；控制逻辑与 4 参数时长模型搬 Rust；拉伸用现成 C 库 libmozart-tempo。 |
| 文件转换队列落盘持久化 | v1 文件任务队列在内存，daemon/rvc 重启丢待转任务。落盘后可续转，长文件任务不白跑。 | daemon | 文件转换链路定稿；任务存储格式与续转/取消语义；板端验证重启续转。 |
