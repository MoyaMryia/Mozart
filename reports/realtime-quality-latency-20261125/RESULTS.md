# 实时变声质量与延迟分步优化实测：Jetson

日期：2026-11-25。对象：实时变声链路自然度四步优化、`IndexSearch` 加速、同机 `--fp16` TensorRT 引擎与 `160 ms` 短块实验。
设备：Jetson Orin Nano Super 8 GB（`MAXN_SUPER`），JetPack 6，TensorRT 10.16。
基线提交：`20e9700`（已包含 `pre` 20 ms 等帧与 2176 样本 ALSA 采播缓冲修复）。

## 适用范围

- 覆盖：ALSA `snd-aloop` 物理回环下的端到端净延迟、30 s 真实中文人声质量指标、60 s 连续稳定性、48 kHz（`bocchi-v2-48k`）与 40 kHz（`tomori-v2-40k`）跨采样率零欠载回归、既有 FP32 资产与本机 FP16 资产对照。
- 未覆盖：物理 USB 声卡/麦克风实录、32 kHz 声学主观听感、`160 ms` 短块跨多模型全量重建。

## 测量方法与配置

- 拓扑：`aplay`（48 kHz S16 双声道）→ `Loopback DEV0,SUB2` → `pre` 采集 `DEV1,SUB2` → `rvc` 实时推理 → `pre` 播放 `DEV0,SUB3` → `arecord` 回录 `DEV1,SUB3`。
- 地板校准（绕过 `pre`/`rvc` 直连回环）：`503.38 ms`（含 `arecord` 提前 0.5 s 启动偏移），净延迟 = 实测起振沿 − 地板。
- 测试信号：
  - 脉冲串（12 s，8 个 0.3 s / 220 Hz 短脉冲，间隔 1.3 s）：测物理回环稳态净延迟（去首脉冲冷启后统计均值与 P95）。
  - 30 s 中文男声（含停顿、清辅音与连读）：与离线文件链参考（同模型 `bocchi-v2-48k`）对齐，测停顿边界最大样本跳变、块边界接缝谱通量比（`seam_flux_ratio`）、高置信窗口 SOLA 滞后游走（相关 > 0.8 的 P95−P5）、Log-Mel L1（dB）与 RMS 包络 L1（dB）。
  - 60 s 连续语料（2×30 s 拼接）：验证长跑帧守恒、`pre_gap_frames`、`playback_underruns`、`capture_overruns` 与 `resets`。
- 主测模型与生效预设：`bocchi-v2-48k`（48 kHz，FAISS 索引 `nlist=3561, ntotal=138915, dim=768`），生效模型默认预设 `pitch_shift=5, index_rate=0.8, rms_mix_rate=1.0, protect=0.4, f0_method=rmvpe`，`pre.dsp.denoise=true`，`skip_silence=true`。
- 跨采样率复测模型：`tomori-v2-40k`（40 kHz，344 MB FAISS 索引，既有 FP32 实时资产）。

## 关键发现与根因

1. **启动缓冲硬下界公式 $D_{\min} = W + T_{\text{infer,max}}$**：
   - `StreamingRvc` 在 `t = k·W` 集齐新块并在 `t = k·W + T_infer` 发布；播放端在 `t = D` 后按 1:1 消耗。因此块完成瞬间的输出环余量为 $D - W - T_{\text{infer}}$。
   - 原始 FP32 推理耗时 `177~206 ms`，对应 $D_{\min} \approx 420~440\text{ ms}$。步骤 A 将 `startup_delay_ms` 扫至 `320 / 280 / 240 / 200 ms` 时，净延迟始终锁在 `581.6~582.0 ms`，`pre_gap_frames` 线性暴涨为 `6 / 7 / 9 / 10`（每次 20 ms 缺帧自愈等价补回 +20 ms 滞后）。只有先压低 $T_{\text{infer}}$ 或 $W$，降低 `startup_delay_ms` 才产生真实的零缺帧延迟收益。
2. **隐藏的 88.6 ms CPU 检索瓶颈**：
   - FP16 引擎实测 GPU 计算耗时已降至 `front 5.51 ms / decoder 6.49 ms / hubert 10.13 ms / rmvpe 5.30 ms`（关闭检索 `index_rate=0` 时整块仅 `54.1 ms`），但开启 `index_rate=0.8` 后飙升至 `142.7 ms`。
   - 分段剖析定位为 `IndexSearch::search()` 对 3561 质心 × 768 维做单线程标量 L2 扫描且逐帧重读 10.9 MB 质心表（每块读主存 153 MB）。引入 ARM NEON 16-float 向量化、32 帧质心分块（质心仅读一次）与 4 线程并行后，检索耗时由 `88.6 ms` 降至 `6.0 ms`（14.8× 提速），单测验证与标量参考精确一致（`max_diff < 1e-4`）。
3. **本机 `--fp16` 声学近无损**：
   - 全部四引擎（`front` / `decoder` / `hubert` / `rmvpe`）使用 `--fp16` 本机编译后，消除既有资产跨设备 TensorRT 警告，且在同预设下 Log-Mel L1 为 `4.864 dB`（FP32 为 `4.742 dB`，仅差 `+0.12 dB`），停顿最大跳变与全局最大跳变均优于基线。
4. **`160 ms` 短块权衡结论**：
   - 160 ms 短块将净延迟进一步压低到 `365.6 ms`（纯 RVC 相对 `direct` 仅 `266 ms`，较基线省 `216.8 ms`），GPU 占空比仅 32.8% 且通过 60 s 零缺帧长跑。
   - 但相比 240 ms 块，Log-Mel L1（`+0.11~0.23 dB`）和 RMS L1（`+0.21~0.35 dB`）略弱，块边界接缝频率提高 1.5 倍（6.25 vs 4.17 缝/s），且会破坏磁盘上所有既有 240 ms 实时资产的形状兼容。因此主干保持 `window_samples = 3840`（240 ms），将 `startup_delay_ms` 默认降至 `340`、`compile.fp16` 默认设为 `true`（本机 FP16 资产可进一步手动配 `startup_delay_ms = 320`）。
