# AEC 采播参考探针：本机与 Jetson 回环

## 结论

`mozart-pre` 可以在不启用声学回声消除（AEC）的情况下记录同一时钟域下的采集与实际 ALSA 接收的播放参考。两次回环中，最长连续交集约 12.2 s；对齐后相关峰只差 1 个样本。该结果支持继续做板端声学录音，不支持选择产品默认后端。

## 配置与口径

- x86_64 Ubuntu 22.04，本机 `snd-aloop`，同一虚拟电缆的 `DEV=0` 播放和 `DEV=1` 采集，48 kHz S16。探针保留首声道。未占用物理麦克风或扬声器。
- `pre` 独立运行，路由设为 RVC，实时支路无输出，避免直通反馈。向播报套接字按 20 ms 节拍注入 600 帧带限随机信号。共运行两次开启探针、两次关闭探针的独立实例。
- 离线以 ALSA 单调时钟状态和队列延迟拟合，不做波形寻峰对齐，不补偿额外声学延迟。归一化互相关在导出的连续交集去掉首尾各 1 s 后计算。

## 同一对齐轨的消除器比较

使用本机 SpeexDSP `1.2~rc1.2-1.1ubuntu3`（200 ms 线性滤波，无后处理）与 WebRTC Audio Processing `1.3-3~ubuntu22.04` 的 AEC3 默认消除器。每次输入 480 样本。两种方法使用同一参考，不按算法或录音分别寻峰。比较窗口为导出轨第 2–10 s；对 AEC3 固定补偿先前测得的 430 样本算法移位，SpeexDSP 为 0。

| 输入 | SpeexDSP 回声衰减，开启 1／2 | AEC3 回声衰减，开启 1／2 |
| --- | ---: | ---: |
| 原始数字回环 | 14.19／14.23 dB | 0.90／0.91 dB |
| 人为对采集轨增加 65 ms 延时 | 27.13／27.11 dB | 38.12／38.07 dB |

这些数字是远端单源测试的 ERLE，即消除前后采集轨能量之比。两种输入下的算法排序不同，不能以数字回环的近零延时评价一般扬声器回声。此处没有人声近端，因此也不能用 ERLE 评价误杀。

## Jetson 隔离回环

Jetson Orin Nano Super 8 GB，R39.2／kernel 6.8.12，MAXN_SUPER。本机交叉构建 ARM64 调试版 `mozart-pre`，在板上独立 `/tmp` 目录运行，使用空闲 Loopback 子设备 7。正式栈继续运行，使用 USB 麦克风和 Loopback 子设备 3。测试前后正式 daemon／pre 的进程身份、配置和二进制 SHA-256 一致，路由、静音、采播设备、文件模式和各服务运行状态一致。

板端 SpeexDSP 1.2.1-1ubuntu3 使用前述同一 200 ms 参数及第 2–10 s 窗口。原始数字回环的 ERLE 为 10.30／26.36 dB；采集轨人为延后 65 ms 后为 27.12／26.92 dB。原始回环两次结果不同，未将其归因于单一因素。每次统计 1,123 个调用（排除首 100 帧），单线程 CPU 时间 p95 为 0.271–0.274 ms，包含 ctypes 调用，不含 I/O、排队或端到端时延。板端只运行 SpeexDSP；AEC3 的数字仍为本机结果。

## 适用范围

两台设备各使用一副虚拟 ALSA 电缆，复用同一个测试信号。数字回环不测 ADC／DAC 到耳延迟、实际时钟漂移、声学失真或反馈稳定性。启用诊断探针时，ALSA 状态查询仍同步执行；它不进入默认运行路径，不用探针模式验收实时性能。

真实双讲尚未测：正式栈占用 USB 麦克风，现役输出为数字 Loopback。解除条件：确认实际外放设备或 Loopback 到外放的链路，并约定可短暂停用正式栈的窗口。先用低增益录制翻译播报打断和同源 RVC 双讲，再据近端失真和残余回声决定运行时方案。
