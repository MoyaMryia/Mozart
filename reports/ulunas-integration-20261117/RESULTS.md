## 接入边界

- 新增 `mozart-enhance` C++ 进程。daemon 管理启动、轮询、退避重启和退出。
- `[enhance]` 选择 UL-UNAS。`pre.dsp.denoise` 控制所选后端；不叠加旧 WOLA。
- 仅增强 FIR 后的共享 16 kHz 输入，再分发至 RVC、ASR 及其他消费者。
- 48 kHz 直通不经过神经模型，不降低其带宽。
- pre 的普通工作线程通过有界队列调用增强进程；采集／播放不等待推理。
- 禁用时不调用网络。错误不静默回退原声，不重送未知结果的音频请求。
- 新连接、帧缺口和开关代次变化重置缓存；文件接管同时等待发送许可归零与输出解绑。
- 自动恢复使用增强启动快照及最近成功的 DSP 开关，不吸收尚未生效的 TOML 值。
- `restart pre`／`restart enhance` 联动重建两者；增加或移除后端要求重启 daemon。
- 文件任务的 `[file].denoise` 保持旧语义；独立离线模式与在线使用同一增强核。

控制与状态：`0x0701` Hello、`0x0702` GetStatus、`status.enhance`、`status.pre.enhancement`。
音频请求为 1300 bytes，应答为 1304 bytes，使用独立 SEQPACKET 会话。
首两帧积攒，此后每请求输出 320 个样本，保留源 `pts_ns` 与 `frame_idx`。

### 真实权重数值对拍

使用完整 Linus 16 kHz 输入，生产离线入口输出 1,391,340 个有限样本，与输入等长。
与此前作者默认窗函数原型比较，固定排除末尾 512 个样本：原型采用文件尾反射，生产流式结束采用零排空。
其他区间的误差 SNR 为 **97.96 dB**，最大绝对误差约 `7.98e-5`，超过预先设定的 60 dB 门槛。

首尾完整性另用恒等模型按生产两帧排空规则逐样本验证，不以截短尾部通过。
真实权重对拍使用 `host-asan`，显式关闭 LeakSanitizer；地址与未定义行为检查保留，不把该运行当作无泄漏证明。

## 板端功能验收

实际环境：Orin Nano Super 8 GB、ARM64、BSP R39.2、MAXN_SUPER。
C++ 使用 `jetson-release`，Rust 使用 debug；ONNX Runtime 1.28.2 CPU、单线程。
推理与运行主体为 C++／Rust，没有 Python 推理依赖。

输入为中文录音的预先指定前 20 s，转换为 PCM16、48 kHz、首声道。
pre 使用文件节拍注入，播放设备为 ALSA `null`。
真实增强、pre、RVC 和 ASR 共同运行；探针不是替代推理的协议桩。

最终 `final-verify.sh` 返回 0，11 个阶段全部通过：

1. 真实 pre、增强和 ASR 就绪。
2. 实时 RVC 产生实际输出帧。
3. 禁用增强后网络调用增量为 **0**，分发仍继续。
4. 重新启用后收到真实增强帧。
5. SIGKILL 增强进程后故障可查询。
6. daemon 自动重启，数据面恢复且清除当前故障。
7. 修改待重启 socket 后杀死 pre，自动恢复仍使用旧生效地址。
8. 显式 `restart enhance` 联动重建并应用新地址。
9. 按既有仲裁规则转直通，释放 GPU 给文件任务。
10. 文件模式实际进入，RVC 实时发送完成交接。
11. 文件任务完成并退出接管，ASR／探针在接管期间仍收到输入。

最终记录：

- 两个独立探针收到 **797 帧逐字节一致**的包；比较键为源时间戳与帧序号。
- ASR 从 0 增至 **5 条 final**，不是只检查进程存活。
- 末次增强会话输入 477 帧、输出 475 帧；差值为两帧积攒，队列深度 0，当前错误为空。
- 文件任务 `job_1794967284088528` 完成，`result_ready=true`、`error=null`。
- 测试目录递归检查实际模型文件数为 **0**；原权重 SHA-256 未变。

### 文件输入到分发端的观测时间

在同一轮运行的预定稳定窗口统计。起点为包内采集事件的 `pts_ns`，终点为探针完成接收。

| 模式 | 样本数 | p50 | p95 | 最大值 |
| --- | ---: | ---: | ---: | ---: |
| 启用增强 | 40 帧 | 45.865 ms | 50.889 ms | 51.880 ms |
| 禁用增强 | 35 帧 | 1.101 ms | 1.200 ms | 1.206 ms |

启用窗口取 RVC 就绪后 0.2–1.0 s，禁用窗口取禁用确认后 0.25–0.95 s。
两者来自不同时间窗，不相减得出配对延迟分布。
该口径包含缓冲、DSP、IPC 与线程调度，不含 ADC／DAC；不能用原型单帧计算耗时代替。

## 适用范围

- 本次完成可选后端的软件接入与上述功能验收，不等于全系统验收完成。
- 最终含故障注入和 RVC／文件并发的运行中，ASR 内部累计丢弃 **41 帧**。没有把它算成零丢帧通过；稳态归因、长跑与整机无丢帧仍按 SPEC-08 保持未完成。
- 文件注入和 `null` 播放不是麦克风／扬声器声学回环，也不提供主观听评分数。
- 当前板端 BSP 与目标 JetPack 6／R36 不同，不外推为该目标软件栈兼容验收。
- 本轮只使用独立测试目录，未执行标准正式部署；正式部署需另行确认窗口与远端开发状态。
